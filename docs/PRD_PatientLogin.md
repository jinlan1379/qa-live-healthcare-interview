# PRD - 患者用户名密码登录

## 1. 概述

### 1.1 功能名称
患者用户名密码登录

### 1.2 版本
v1.0

### 1.3 作者
AI 辅助开发

### 1.4 日期
2026-11-04

### 1.5 背景
当前系统患者通过姓名+生日进行身份验证，安全性较低。为提升用户体验和安全性，需要新增用户名密码登录方式，支持患者注册和登录功能。

## 2. 目标

### 2.1 业务目标
- 提供标准的用户名密码认证机制
- 允许新患者自主注册账户
- 为后续更多安全特性（如密码加密、JWT token）打好基础

### 2.2 用户目标
- 患者可以通过用户名和密码快速登录系统
- 新患者可以自主注册账户
- 登录后可以使用问诊服务

### 2.3 非目标
- 本版本不实现密码加密存储（演示项目）
- 不实现 JWT token 认证
- 不实现密码找回功能

## 3. 用户故事

### 3.1 目标用户
患者用户 - 需要通过平台向医生问诊的用户

### 3.2 用户故事列表
- 作为患者，我希望用用户名和密码登录，以便快速进入问诊系统
- 作为新患者，我希望注册一个账户，以便后续多次使用
- 作为患者，我希望登录后自动跳转到问诊页面，以便立即开始问诊

## 4. 功能需求

### 4.1 功能列表
| 编号 | 功能 | 优先级 | 描述 |
|------|------|--------|------|
| F1 | 患者登录 | P0 | 用户名+密码登录 |
| F2 | 患者注册 | P0 | 新用户注册，填写用户名、密码、姓名 |
| F3 | 登录状态保持 | P1 | 登录后在 store 中维护当前患者状态 |
| F4 | 导航栏入口 | P1 | 在 header 添加患者登录入口 |

### 4.2 详细描述

**F1 - 患者登录**
1. 用户打开患者登录页面 `/patient/login`
2. 输入用户名和密码
3. 点击登录按钮
4. 系统调用 `POST /api/patients/login` 验证
5. 成功则跳转到问诊页面 `/consultation`
6. 失败则提示"用户名或密码错误"

**F2 - 患者注册**
1. 登录页面提供"注册"切换链接
2. 输入用户名、密码、姓名
3. 系统调用 `POST /api/patients/register`
4. 成功则自动登录并跳转到问诊页面
5. 用户名已存在则提示"用户名已存在"

## 5. 界面设计

### 5.1 页面列表
- 患者登录/注册页面 `/patient/login`

### 5.2 交互流程
```
首页/导航栏 → 点击"患者登录" → 登录页面 → 输入凭证 → 登录成功 → 问诊页面
                                        ↓
                                   切换到注册 → 填写信息 → 注册成功 → 问诊页面
```

## 6. 技术要求

### 6.1 API 接口
- `POST /api/patients/login` - 患者登录
  - Request: `{ username, password }`
  - Response: `{ success, message, user }`
- `POST /api/patients/register` - 患者注册
  - Request: `{ username, password, name, gender?, phone? }`
  - Response: `{ success, message, user }`

### 6.2 数据模型
Patient 表（已在 init.sql 中创建）:
- id, username, password, name, birthday, phone, gender

### 6.3 安全要求
- 本版本为演示项目，密码明文存储
- 文档中说明未实现完整认证方案
